# 交叉题库：风控 × 智能体（含答案锚点）

这部分是复合岗的核心竞争力区，也是面试官最想验证"你是不是只会一半"的地方。
通用规律：**风控侧永远是约束方（合规、可解释、可复现、责任可追溯），智能体侧是效率方**。回答能同时讲清两侧的张力，就是资深信号。

---

## C1 类 · 落地场景题

**C101｜用 Agent 做信贷审批辅助，怎么保证合规与可解释？**
- 必答：
  - 定位为"辅助"而非"决策"——最终授信由人或策略引擎做出，Agent 只做信息汇总、材料核验、要点提示。
  - 可解释：每个结论必须带证据链（哪个文件、第几页、哪条规则），拒绝理由要映射到标准拒贷原因码，不能输出自由文本当理由。
  - 合规：数据不出域、留痕完整、模型版本可追溯、对特定群体做公平性检验。
- 加分：把"模型输出"与"决策规则"解耦——Agent 输出结构化证据，规则引擎出决策，这样监管问"为什么拒"时有确定性答案；建立人工复核抽样与申诉通道。
- 陷阱：让 Agent 直接输出"建议拒绝"，且无法说明依据。

**C102｜把风控策略知识灌进 RAG，怎么验证没被污染、没过期？**
- 必答：
  - 知识源头要单一可信（制度库/策略配置库），不从聊天记录、旧文档抓。
  - 每篇文档带元数据：生效日期、失效日期、版本号、适用产品线、密级，检索时按时间与产品过滤。
  - 建"知识一致性"检查：同一问题在不同文档中的答案是否冲突，冲突时以生效日期最新且层级最高者为准。
  - 评测集里必须放"过期陷阱题"——用已废止规则提问，看它是否答旧口径。
- 加分：策略规则本质是结构化配置，优先从配置库直接读而不是靠文档检索（结构化数据不该走 RAG）；文档型知识才走 RAG。
- 陷阱：把 PDF 制度文件直接切块入库，不标版本和生效期。

**C103｜让 LLM 生成策略规则或评分卡变量，你怎么评估它靠不靠谱？**
- 必答：
  - 不让模型直接产出结论规则，而让它产出**候选假设**，再由数据验证——在 OOT 上算命中量、坏账率、IV、增量价值。
  - 防"看起来合理但统计不显著"：设最小样本门槛，做显著性检验，做过拟合惩罚（规则数上限）。
  - 检查逻辑一致性：规则是否与已知业务常识冲突（如"收入越高越坏"），冲突的要人工复核而非直接采纳。
- 加分：LLM 擅长的是"提出可验证的假设"和"把业务经验翻译成可计算的表达式"，不擅长的是"判断统计有效性"——分工要清。
- 陷阱：用 LLM 生成规则后直接上线，或用 LLM 自评"这条规则好不好"。

**C104｜用 Agent 做贷后监控告警，怎么降噪？**
- 必答：
  - 分两层：统计层（规则/模型算出异常信号）+ 解释层（Agent 把多个信号聚合成一条可读的告警，附影响面与建议动作）。
  - 降噪手段：告警聚合（同一客户/同一渠道合并）、去重（抑制重复触发）、分级（按金额与风险等级路由到不同人）、抑制窗口。
  - 关键指标：告警准确率（真阳性占比）、漏报率、人均有效告警数、处置时长。
- 加分：Agent 的价值不在"发现异常"（统计模型更擅长），而在"解释异常、给出处置建议、写清楚来龙去脉"，把人从看板里解放出来。
- 陷阱：让 Agent 直接判"这个客户要爆雷"，且不给出信号来源。

**C105｜风控场景的 Agent 评测指标怎么定？（不能只看准确率）**
- 必答：至少四类——
  - 正确性：结论与人工专家判断的一致率（分层看，坏人漏判比好人误判更致命）。
  - 可追溯性：结论能否指回原始证据（引用覆盖率）。
  - 稳定性：同一输入多次运行结论是否一致（风控要求可复现）。
  - 效率：单笔处理时长、人工复核率、成本。
- 加分：指标要能对应业务损失——把"漏判率"换算成预期坏账，把"误判率"换算成通过率损失，这样评测结果才能进入决策。
- 陷阱：只报一个整体准确率。

**C106｜用 Agent 做材料审核（流水、财报、征信报告），难点在哪？**
- 必答：
  - 文档异构（扫描件、表格、多栏排版），解析质量决定上限。
  - 关键字段抽取要精确（金额、日期、账号），错一位就错全部，必须做交叉校验（流水余额连续性、财报三表勾稽）。
  - 造假识别：图像篡改、PS 痕迹、逻辑矛盾（收入与流水不符）。
- 加分：把"抽取"和"判断"分开——抽取用确定性工具+校验规则，判断才用模型；输出要标注置信度并路由人工。
- 陷阱：让模型一眼看完整份财报直接给结论。

**C107｜风控知识库给 Agent 用，权限怎么设计？**
- 必答：数据分级（客户隐私、策略参数、模型细节分别定密级）；检索层做行级/文档级权限过滤（不能靠 prompt 说"不要泄露"）；不同角色（审批员、策略分析师、外部审计）看到的知识范围不同。
- 加分：策略参数这类高敏知识宁可不让 Agent 检索，改为受控 API 返回脱敏结果；所有检索行为要审计。
- 陷阱：靠系统提示词约束保密。

**C108｜Agent 给出了错误的信贷建议，责任怎么划？**
- 必答：责任在部署方（机构），不在模型。所以设计上要保证：人可复核（human-in-the-loop）、决策可追溯（谁在什么信息下做的决定）、有申诉与纠错通道、有明确的模型使用边界（哪些场景禁用）。
- 加分：区分"建议错误"与"流程失守"——多数事故根因是流程没有复核环节，而不是模型不够准。
- 陷阱：说"这是模型的问题"。

**C109｜业务人员问"这个客户为什么被拒"，怎么做一个能答的助手？**
- 必答：不能靠模型自由生成理由。做法：从决策引擎取结构化的拒绝原因码 + 命中规则 + 关键变量分箱位置，由 Agent 组织成自然语言解释；每个理由必须能指回具体规则 id 与阈值。
- 加分：解释要分层——给业务看"命中哪条规则"，给客户看"标准化拒贷原因"，给审计看"完整决策路径"；同时要防止解释被用于"教客户绕过规则"（反欺诈考虑）。
- 陷阱：让模型读一遍客户数据自己编理由。

**C110｜模型文档、监管报送这类重复文档，能自动化到什么程度？**
- 必答：能自动化到"草稿+校对"，不能到"直接提交"。可行：从模型工程库自动取指标（KS/AUC/PSI）、从版本库取变更记录、按模板生成章节；必须人工确认的是口径描述、局限性说明、以及对外承诺。
- 加分：这类场景更适合"结构化数据 + 模板渲染"而非纯 LLM 生成——数字必须来自系统而非模型复述。
- 陷阱：让模型"总结一下模型表现"然后直接上报。

## C2 类 · 项目拷问模板

针对简历里的项目，按以下顺序逐层下钻。每层都可能停在这里追问，也都可以跳层（若回答已足够好）。

**第一层：背景与你的角色**
- 这个项目解决什么问题？谁提的需求？你负责哪部分，团队几个人？
- 追：如果只让你保留一个指标证明项目成功，是哪个？

**第二层：方法与取舍**
- 为什么选这个方案？当时考虑过哪些替代方案，为什么没选？
- 追：这个方案的假设是什么？假设不成立会怎样？

**第三层：数据与验证**
- 数据从哪来、多大量、坏样本多少、表现期多久？
- 怎么验证的？OOT 还是随机切分？指标多少？跟基线比提升了多少？
- 追：提升是模型带来的还是策略/流程带来的？怎么排除？

**第四层：上线与效果**
- 上线后实际效果和离线差多少？差在哪？
- 出了什么问题？怎么发现、怎么修的？
- 追：如果线上突然劣化，你的排查顺序是什么？

**第五层：反思与延伸**
- 现在回头看，哪里会改？当时最大的误判是什么？
- 如果数据量涨 100 倍 / 如果要做成通用产品，方案要怎么变？

**评分提示**：能顺畅走完五层且每层都有具体数字与具体坑的，是资深信号；到第三层就含糊的，按中级评；到第二层只会说"领导定的"的，按初级评。

## C3 类 · 高压质疑题

**C301｜"你说的这些，我觉得没多大价值，规则就能搞定。"**
- 期望反应：不辩解、不盲从。先确认对方关注的维度（成本？稳定性？），再用具体数字说明增量价值，同时承认规则在哪些场景确实更优。能说"如果只追求 X，那规则确实够了"是高分手。
- 扣分：情绪化反驳，或立刻全盘妥协说"您说得对"。

**C302｜"我们团队没有大模型经验，你来了怎么落地？"**
- 期望反应：给出渐进路径（先做低风险高价值的辅助场景 → 积累评测与工具链 → 再碰核心决策）、明确先不做什么、说明如何用最小成本验证。要有"先建评测集再谈模型"的意识。
- 扣分：上来就讲架构蓝图，不谈第一步怎么走。

**C303｜"你为什么从风控转（或兼）做智能体？"**
- 期望反应：说清能力叠加而非逃离——风控给了你"如何验证一个模型是否可信"的方法论，智能体给了你"处理非结构化信息"的工具；两者结合点是可解释、可评测、可追溯。
- 扣分：贬低原方向，或只说"因为 AI 是趋势"。

## 出题配比建议

复合岗一场 45 分钟技术面，建议配比：
- 风控 40%：L2 为主，至少 1 道归因题（R302/R207）+ 1 道陷阱题
- 智能体 40%：L2 为主，至少 1 道评测题（A204）+ 1 道可靠性题（A301）
- 交叉 20%：至少 1 道 C101/C103/C105

若用户目标岗偏风控，交叉题比例提到 30%、智能体降到 30%；反之亦然。
