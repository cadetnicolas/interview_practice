# 出题：从材料生成，不用固定题库

## 为什么

固定题库测的是记忆力。真实面试官追的是**只有这个候选人能答的事**——他做过什么、当时怎么决定、错在哪。拿一张通用题目清单去问，得到的是通用回答，练完了到考场照样露馅。

所以这里的规则是硬性的：**题目一律现场生成，不给现成清单。**

## 唯一检验标准

出任何一题前，问自己一句：

> **这题是不是只有这个候选人会被问到？**

- **是** → 好题。因为它挂在他的具体经历上，别人答不了。
- **否** → 这是知识题（"KS 和 AUC 有什么区别"），不是面试题。要么删掉，要么改造成挂在他经历上的问法。

第二道自检：**这题我能不能追到第三层？** 追不到的题，问完就没了，测不出深度。

第三道：**这题有标准答案吗？** 有 → 那是考试题。面试题应该只有"他的答案合不合理"，没有"正确答案"。

## 一、从简历提取可攻击点

简历只有两种句子有价值：**带数字的**，和**带动词的**。其余都是装饰。逐句扫，标出下面八类问题。

### 1. 数字孤岛 — 有结果，没有基线和口径

简历写法：「KS 从 0.38 提升至 0.45」「准确率 92%」「效率提升 40%」

- 风控问法：「0.45 在什么样本上测的？OOT 还是随机切分？」
- 智能体问法：「92% 是谁标的？多少条样本？难例占多少？」
- 追到第二层：提升来自新变量、新样本，还是换了口径？
- 追到第三层：上线后实际是多少？

### 2. 团队隐身 — 满篇「我们」，没有「我」

简历写法：「我们团队搭建了风控体系」「参与设计 Agent 架构」

- 通用问法：「哪一步是你拍板的？换个人能不能做？」
- 追到第二层：如果这步错了，你会怎么发现？
- 这是**最高频的失分点**，几乎每份简历都有。

### 3. 方法跳跃 — 直接说用了什么，没说为什么

简历写法：「采用 XGBoost 建模」「基于 LangChain 搭建多智能体」

- 风控问法：「为什么不用逻辑回归？可解释性怎么处理？」
- 智能体问法：「为什么单 Agent 加工具不够？」
- 追到第二层：这个选择牺牲了什么？

### 4. 无失败叙事 — 全程顺利，没有一个坑

简历写法：整段只有成果，没有"踩过什么坑"

- 通用问法：「这个方案当时最大的风险是什么？后来出问题了吗？」
- 追到第二层：现在回头看会改哪里？
- 全程无失败的简历，要么是假的，要么他没真正参与。**必须问。**

### 5. 结论过强 — 因果关系说得太满

简历写法：「通过优化策略，坏账率下降 30%」「引入 RAG 后问题解决」

- 风控问法：「同期大盘什么走势？客群结构变了吗？怎么排除是环境带来的？」
- 智能体问法：「是 RAG 解决的，还是同时改的 prompt 也有份？」
- 追到第二层：有没有做过对照？

### 6. 规模含糊 — 数据量、用户量、团队规模不清

简历写法：「海量数据」「大规模用户」「核心系统」

- 通用问法：「具体多少？百万还是千万？峰值 QPS 多少？」
- 追到第二层：这个量级下，你原来的方案哪里会撑不住？

### 7. 时间断层 — 项目周期与声称的工作量不匹配

简历写法：三个月做了五个项目；或一个"从 0 到 1"只写了两个月

- 通用问法：「这个项目你实际投入多少时间？同时在忙什么？」
- 用途：验证真实性，**不要用来审问**，语气要平。

### 8. JD 错配 — 简历有的 JD 不要，JD 要的简历没有

- 简历有、JD 没有 → 问「为什么想从 A 转到 B」，看他是否想清楚
- JD 要、简历没有 → 问「这块你没做过，你会怎么上手」，看迁移能力
- 这类题考的是**动机与迁移**，不是技术。

## 二、从 JD 提取必须验证的能力

JD 里真正有信息的是**动词**和**隐含要求**：

| JD 写法 | 真正在要什么 | 怎么问 |
|---|---|---|
| 负责 / 搭建 / 从 0 到 1 | 独立判断力 | 问一个没有标准答案的取舍 |
| 优化 / 提升 | 归因能力 | 问"怎么证明是你带来的" |
| 推动 / 协同 / 跨部门 | 处理冲突 | 问一次意见相反的经历 |
| 深入理解 / 精通 | 深度 | 挑一个点往下追三层 |
| 熟悉 XX 技术栈 | 别问名词，问边界 | 「XX 什么情况下不该用」 |

**不要**问 JD 里的名词解释。会背 JD 的人都会答。

---

## 三、交叉选点

优先级从高到低：

1. **简历可攻击点 ∩ JD 必须验证** — 最高优先级，一题顶三题
2. 简历可攻击点（JD 没提但看得出是硬伤）
3. JD 必须验证（简历完全没覆盖，考迁移）
4. 用户自己担心的那一点 — 一定要问，这是他来的理由

用户没主动说担心什么，就在对齐阶段问出来。

## 四、五种句式

生成题目时只用这五种，其余句式多半是废话。

| 句式 | 模板 | 打什么 |
|---|---|---|
| **追证** | 你说 X 提升了，基线和口径是什么？ | 数字真伪 |
| **反例** | 有没有它不成立的情况？ | 边界意识 |
| **取舍** | 当时有哪两个选项，你为什么选这个？ | 判断力 |
| **规模** | 如果量级变成 100 倍（或 1/10）呢？ | 方案弹性 |
| **归因** | 怎么证明这是你这个改动带来的？ | 因果严谨 |

题干要短。一句话说完，不要加"请详细阐述"。

## 五、出题前自检

写完一题，过一遍：

- [ ] 只有这个候选人会被问到吗？（否则是知识题）
- [ ] 挂在他简历的哪一句上？能指出来吗？
- [ ] 我能追到第三层吗？第二层、第三层分别问什么？
- [ ] 这题有标准答案吗？（有就说明问错了）
- [ ] 问完之后，我能判断他行不行吗？（不能就是废题）

五条里有一条不过，重写。

## 六、没有简历时

用户拒绝给简历，就做**情景题**，不是知识题。

情景题必须带约束，否则答出来是空的：

```text
你在一个日申请量 5 万、坏样本占比 2% 的现金贷产品做策略。
现在要通过率提高 5 个点，但坏账率不能涨超过 20bp。
你手上只有 12 个月的放款数据和一个上线的评分卡。你怎么做？
```

对比无效情景题：「你怎么做风控策略？」——这种题谁都能答，答了也测不出东西。

**必须声明**：复盘里写明「无简历对照，本场为情景题」。分数不与有简历的场次横向比较。

## 七、考点地图怎么用

`references/coverage/` 下的文件是**考点地图**，不是题目池。三不用、两用：

**不用来：**
- 抽题（不许按上面的条目出题）
- 平推（不许照着考点清单从头问到底）
- 逐条覆盖（不许为了"全面"把考点都问一遍）

**只用来：**
- **校验覆盖**：这场我考了哪几个维度？有没有漏掉关键维度？
- **校准评分**：他答的这个点，什么算过线、什么算假好、该往哪追

换句话说：**先从他简历里出题，答完之后再翻考点地图，看这一答落在哪个考点上、该给几分。**

## 八、一场的题目来源配比

以 4 题为例：

- **2 题**来自简历可攻击点（其中至少 1 题打在「团队隐身」或「数字孤岛」上）
- **1 题**来自 JD 缺口（考迁移）
- **1 题**来自用户担心的那一点
- 压力测试（陷阱题）**不单独占题**，挂在某道题的第二层追问上

题量加到 6 题时，多出的 2 题优先给简历里最可疑的两段经历。
