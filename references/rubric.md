# 评分与复盘

## 一、评分单位

**维度 × 权重**。维度和权重来自本场使用的岗位包（`roles/credit-risk.md`、`roles/agent-dev.md`，或临时岗位包）。HR 初筛轮用 `rounds.md` 里的临时权重。

- 没考到的维度写「未考察」，**不补分、不按均分推算**。
- 一场里没考到核心维度，就不能说「到了通过线」，只能给当前已考察部分的分数。

## 二、1–5 分通用语义

岗位包描述「这个维度答得好长什么样」，这张表描述「几分是什么水平」。两者叠加使用。

| 分 | 含义 |
|---|---|
| 1 | 没答上，或出现材料里不存在、用户也没讲过的事实（编造） |
| 2 | 有相关话题，但没有可验证的证据、判断或个人动作 |
| 3 | 有结构，但关键要素（证据 / 角色 / 取舍）仍不清楚 |
| 4 | 要素清楚，追问后还站得住 |
| 5 | 追问后能补上约束、失败和复盘，且与材料一致 |

**半档不给。** 拿不准时给低的那一档。

## 三、通过线

两个条件**都满足**才算到了这一轮的通过线：

1. 已考察的核心维度都 ≥ 3；
2. 按权重计算的加权均分 ≥ 3.5。

加权均分 = Σ(维度分 × 权重) / Σ权重，保留一位小数。

分数只说明**离通过线还差什么**，不预测能否拿到 offer。

## 四、红线（优先于一切加分）

命中任一条，**该维度最多 2 分**，并在复盘里明确点名：

1. **编造**：虚构项目规模、客户、收益、样本量、指标，或引用了不存在的论文/标准/监管条文。
2. **合规越界**：主张用客户隐私数据训练、主张绕过审批、主张用不可解释模型做拒贷且不做任何解释、主张美化报送数据。
3. **推责**：把事故全推给环境、模型或他人，无自我复盘。（终面尤其看重此项。）
4. **假好**：背诵框架名、堆砌空泛词、把团队结果说成个人结果、给精确但无来源的数字。
5. **防御性抵抗**：被追问时既不给论证，也不承认不确定，只靠语气撑。

> 红线不是扣分项，是**该维度作废**。面试中这类回答的杀伤力远大于知识盲区。

## 五、复盘格式

出戏后再写。**必须引用用户原话。**

```markdown
## 结论
到了 / 还没到这一轮的通过线。加权均分：X.X（通过线 3.5）。最弱：维度名（分数）。

## 分数
- 维度（权重）：分数。原话：「……」缺口：……
- 维度（权重）：未考察

## 最弱一题改写
题目：
你的原话：
改写：只用已经说过的事实；空缺写成〔待你补充：……〕
如果重答，这样开头：「……」
不要背这段。空缺是你要补的事实，不是更华丽的措辞。

## 优先改进
最多 3 条，每条对应一个缺口。

## 下一轮只练
维度：
题量：2
```

配套纪律：

- **先结论后细节**，不要开场夸三句。
- 夸要具体到「你提到了 XX，这点很多人会漏」，不夸「回答得不错」。
- 缺点必须配改法，否则用户不知道怎么改。
- 「优先改进」最多 3 条，列 5 条等于没重点。
- 触红线的题目单独标出，说明为什么是红线。

## 六、通用「假好」识别

岗位包里已经写了各维度专属的「假好」。以下是跨领域的通用信号，命中任一即不得高于 3 分：

| 信号 | 长什么样 | 怎么破 |
|---|---|---|
| 术语连发 | 一口气说七八个名词，但不解释任何因果 | 挑一个追问：「你刚说 KS 受通过率影响，具体怎么影响？」 |
| 万能句式 | 「要结合业务实际」「看具体情况」「多维度综合评估」 | 「具体到这个场景，你选哪个？」 |
| 只讲流程不讲判断 | 「先数据清洗，再特征工程，再建模……」 | 「哪一步最容易出错？你怎么发现的？」 |
| 借力他人 | 「我们团队用了 XX 方案」，说不清为什么 | 「为什么选它不选另一个？」 |
| 数字含糊 | 「效果提升明显」「大概二三十」 | 「具体多少？什么口径下测的？」 |
| 完美无缺 | 全程没有失败、没有取舍、没有代价 | 「这个方案的风险是什么？你当时担心哪一点？」 |

## 七、定级与档案刻度

档案里存百分制，与 5 分制的换算：`百分制 = 加权均分 ÷ 5 × 100`。

| 加权均分 | 百分制 | 定级 | 对应岗位就绪度 |
|---|---|---|---|
| ≥ 4.25 | ≥ 85 | L3 就绪 | 可面资深/负责人岗，重点补组织与归因叙事 |
| ≥ 3.5 | ≥ 70 | L2 就绪 | 可面 3–5 年岗，需补 1–2 个薄弱维度 |
| ≥ 2.75 | ≥ 55 | L1–L2 | 可面初级岗，深度与落地感待补 |
| < 2.75 | < 55 | L1 | 需系统补基础，先补 `coverage/` 里的基础考点 |

定级是**相对于目标岗位**的判断。用户目标是资深岗时，3.5 分意味着明显不足。
