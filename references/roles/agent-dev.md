# 岗位包：智能体 / 大模型应用开发

对齐时先确认条线，再按追问重点调整。**维度权重不变。**

## 条线

- **应用 / 产品向**：场景选择、用户价值、上线路径、效果与成本的平衡
- **Agent 工程**：编排、工具设计、上下文工程、可靠性、可观测
- **RAG / 知识库**：解析、切块、检索、重排、知识时效与权限
- **评测 / 数据**：评测集建设、指标设计、人工标注、数据飞轮
- **平台 / 架构**：多租户、模型路由、成本治理、灰度与回滚
- **未说明**：先问条线，不要开题

## 维度

| 维度 | 权重 | 好证据 | 假好 |
|---|---|---|---|
| 方案判断 | 25 | 说得出为什么用（或不用）Agent、为什么是这个架构、替代方案差在哪 | 堆框架名（LangChain / AutoGen / 多智能体），讲不出取舍 |
| 工程可靠性 | 25 | 失败路径清晰：幂等、超时重试、降级、人工接管、成本与延迟数字 | 只讲效果不讲失败；被问"模型错了怎么办"就答"优化 prompt" |
| 评测与验证 | 20 | 有私有评测集、分层指标、难例回归、基线对比 | 只报一个「准确率 95%」，说不清分布和口径 |
| 业务落地 | 15 | 真实用户、灰度路径、权限与数据隔离、上线后监控 | demo 思维，把演示效果当成产品效果 |
| 个人贡献 | 15 | 说得清自己拍板的那一步（检索策略、tool schema、评测集） | 团队成果，个人动作模糊 |

## 追问

- 什么时候**不该**用 Agent？你这个场景属于哪边？
- 失败率多少？失败长什么样？用户能发现并纠正吗？
- 答案错了，是没检索到，还是检索到了但生成跑偏？怎么区分？
- 成本和延迟是多少？瓶颈在哪一环？
- 评测集怎么建的？有没有被污染？难例占比多少？
- 上线后效果劣化，你怎么发现？发现后怎么办？
- 如果模型换成小一号的，哪些能力会掉？

## 红旗

出现即该维度最多 2 分：

- 只讲 demo 效果，不讲失败率和兜底
- 用「模型能力再强一点就好了」回答工程问题
- 报准确率不给分布、口径和错误类型
- 说不清自己具体做了什么
- 把「多智能体」当成高级的同义词

## 切入点

这不是题目清单，而是**这个维度通常从哪类经历里被问出来**。拿它去匹配候选人的简历，命中哪条就现场编一题。

| 简历里出现 | 往哪问 |
|---|---|
| Agent / 智能体 / 自主执行 | 为什么必须是 Agent，不用它差在哪 |
| 多智能体、编排、工作流 | 单 Agent 加工具为什么不够，协调成本多少 |
| RAG、知识库、检索 | 检索命中率多少，答错是没检索到还是答偏了 |
| 微调、训练、模型优化 | 为什么不走 RAG，知识怎么更新 |
| 工具调用、function calling | 模型选错工具怎么发现，错误能自愈吗 |
| 上下文、记忆、长文档 | 装不下时丢什么，怎么保证不丢关键约束 |
| 上线、用户量、成本 | P95 延迟多少，瓶颈在哪，失败怎么兜 |
| 准确率、评测、效果 | 评测集哪来的，有没有污染，错的是哪类 |
| 只有「我们」没有「我」 | 哪一步是他拍板的，换个人能不能做 |
| 内部工具、给业务用 | 权限在哪一层拦，出错谁负责 |

答完之后去 `references/coverage/agent-dev.md` 查该考点什么算过线、往哪追。
