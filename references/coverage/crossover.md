# 考点地图：风控 × 智能体交叉

**这不是题目池。** 交叉岗的题尤其必须从简历里长出来——因为复合岗的核心不是"会不会两个领域"，而是"能不能同时处理两边的张力"。

用途：他答完之后查这里，判断这一答落在哪个考点、该给几分、该往哪追。

**通用规律**：风控侧永远是约束方（合规、可解释、可复现、责任可追溯），智能体侧是效率方。回答能同时讲清两侧张力的，才是资深信号；只讲一侧的，该维度最高 3 分。

---

## 一、落地场景

### Agent 辅助审批的合规与可解释
**触发**：简历提到"用大模型辅助审批/尽调/风控"
**好回答**：定位为辅助而非决策——最终授信由人或策略引擎做出；每个结论带证据链（哪个文件、第几页、哪条规则）；拒绝理由映射到标准原因码，不能输出自由文本当理由；数据不出域、留痕完整、版本可追溯、做公平性检验
**假好**：让 Agent 直接输出"建议拒绝"，且无法说明依据；用"AI 比人准"论证
**追问**：① 监管问"为什么拒"，你能指到哪 → ② 模型输出和决策规则怎么解耦 → ③ 人工复核抽多少

### 知识库时效与污染
**触发**：简历提到"把制度/策略文档灌进知识库"
**好回答**：知识源头单一可信（制度库/策略配置库），不从聊天记录和旧文档抓；每篇带元数据（生效日、失效日、版本、适用产品线、密级），检索时按时间与产品过滤；建一致性检查，冲突时以最新且层级最高为准；评测集要放"过期陷阱题"
**假好**：PDF 直接切块入库，不标版本和生效期；用 RAG 读本该结构化的策略配置
**追问**：① 制度改了怎么同步 → ② 两个文档冲突听谁的 → ③ 怎么测它没答旧口径

### LLM 生成策略规则的验证
**触发**：简历提到"用大模型生成规则/变量/策略建议"
**好回答**：不让模型直接产出结论规则，而是产出**候选假设**，再由数据验证——在 OOT 上算命中量、坏账率、IV、增量价值；设最小样本门槛、做显著性检验、限制规则数防过拟合；规则与业务常识冲突时人工复核而非直接采纳
**假好**：LLM 生成规则后直接上线；用 LLM 自评"这条规则好不好"
**追问**：① 怎么验证统计有效 → ② 规则数量上限怎么定 → ③ 模型说得通的规则数据不支持，听谁

### 告警降噪
**触发**：简历提到"贷后监控""智能预警""风险提示"
**好回答**：分两层——统计层算异常信号，解释层把多信号聚合成可读告警并附影响面与建议动作；降噪靠聚合、去重、分级、抑制窗口；指标看告警准确率、漏报率、人均有效告警数、处置时长
**假好**：让 Agent 直接判"这个客户要爆雷"，不给信号来源
**追问**：① 它是发现异常还是解释异常 → ② 漏报和误报哪个更贵 → ③ 降噪后准确率多少

### 风控场景的评测指标
**触发**：简历提到"评测""准确率"
**好回答**：四类指标——正确性（与人工专家判断一致率，分层看）、可追溯性（引用覆盖率）、稳定性（同输入多次运行是否一致）、效率（时长、复核率、成本）；指标要能换算成预期坏账与通过率损失
**假好**：只报一个整体准确率
**追问**：① 漏判和误判哪个更致命 → ② 怎么测一致性 → ③ 这个分数对应多少坏账

### 材料审核（流水/财报/征信）
**触发**：简历提到"材料审核""自动识别""尽调报告"
**好回答**：解析质量决定上限（扫描件、表格、多栏）；关键字段要交叉校验（流水余额连续性、三表勾稽）；造假识别看图像篡改与逻辑矛盾；把"抽取"和"判断"分开——抽取用确定性工具+校验，判断才用模型；输出带置信度并路由人工
**假好**：让模型看完整份财报直接给结论
**追问**：① 抽错了怎么发现 → ② 怎么验证资料造假 → ③ 置信度低的怎么处理

## 二、边界与责任

### 权限与数据隔离
**触发**：简历提到"内部工具""给业务用"
**好回答**：数据分级（客户隐私、策略参数、模型细节分别定密级）；检索层做行级/文档级权限过滤，不靠 prompt 约束；高敏知识宁可不检索，改受控 API 返回脱敏结果；检索行为要审计
**假好**：靠系统提示词约束保密
**追问**：① 权限在哪一层拦 → ② 策略参数会不会被查出来 → ③ 谁查过什么能追溯吗

### 责任归属
**触发**：简历提到"决策建议""自动审批"
**好回答**：责任在部署方（机构）不在模型；设计上要人可复核（human-in-the-loop）、决策可追溯（谁在什么信息下决定）、有申诉纠错通道、有明确禁用场景；多数事故根因是流程没有复核环节，不是模型不够准
**假好**：说"这是模型的问题"
**追问**：① 出错谁负责 → ② 用户怎么申诉 → ③ 哪些场景绝对不许用

## 三、项目拷问结构（不是题目）

这是**追问的骨架**，用来把一段经历挖到底。具体问什么，仍然从他的简历里取。

五层，每层都可能停，也可能跳层（若回答已足够好）：

1. **背景与角色**：解决什么问题、谁提的需求、你负责哪部分、团队几个人
2. **方法与取舍**：为什么选这个方案、考虑过哪些替代、假设是什么、假设不成立会怎样
3. **数据与验证**：数据从哪来、多大量、坏样本多少、表现期多久、OOT 还是随机切分、跟基线比提升多少
4. **上线与效果**：上线后差多少、差在哪、出过什么问题、怎么发现怎么修
5. **反思与延伸**：现在会改哪里、当时最大的误判是什么、量级涨 100 倍会怎样

**评分提示**：能走完五层且每层都有具体数字与具体坑的，是资深；到第三层就含糊的，按中级；到第二层只会说"领导定的"，按初级。

**必追的一句**（放在第 3 或第 4 层）：「提升是模型/方案带来的，还是策略、流程或环境带来的？怎么排除？」

## 四、压力测试手法（不是题目）

用于测抗压与判断，**不要单独占一道题**，挂在某道题的追问上。每场最多用一次。

| 手法 | 怎么说 | 看什么 |
|---|---|---|
| **否定价值** | 「你说的这些我觉得规则就能搞定。」 | 不辩解不盲从；能否用数字说明增量，同时承认规则在哪些场景更优 |
| **资源质疑** | 「我们团队没这方面经验，你来了怎么落地？」 | 是否有渐进路径、先不做什么、最小成本验证 |
| **动机质疑** | 「你为什么从风控转做智能体？」 | 是否说清能力叠加而非逃离；贬低原方向的扣分 |
| **归因逼问** | 「怎么证明这是你带来的？」 | 是否承认归因难度并给三角验证，而非直接认领 |
| **规模升维** | 「样本量变成 1/10 呢？」 | 方案弹性，而不是硬套原方案 |

**好的反应**：先确认对方关注的维度，再给具体论证，同时承认适用边界。
**扣分反应**：情绪化反驳，或立刻全盘妥协说"您说得对"。
